# 簡潔な文章

読者が一度で読める長さと構造にし、意味を保ったまま短くする。
基準の全文は [文章作成基準](references/writing-standard.md) にある。

## 適用範囲

対象は次の文章とする。

- Markdown 文書と、CLAUDE.md や SKILL.md などの AI 向け指示文書
- Issue、PR、レビューコメント
- ユーザーへの回答。行動規範だけを適用し、数値は逐次検査しない

コード、コマンド出力、引用、既存文書の一括書き換えは対象外とする。

## 推敲手順

1. 読者と用途を決め、結論と必要な行動を先頭に置く。
2. ファイル文書は検査し、警告の妥当性を確認する。
3. 内容と表示を保って修正する。必要なら再検査する。

段落の長さ、構成、語彙、重複は手順 3 で自分で確認する。

## 機械検査

```bash
bash ~/Projects/tool/dotfiles/infra/ai/check-prose.sh <file.md>...
```

- 静的な Markdown を新規作成したとき、または大きく改稿したときに実行する。
- Issue や PR の本文は一時ファイルに写して検査してよい。
- 終了コード 2 は実行できなかった状態であり、検査結果ではない。導入手順を伝え、勝手に依存を入れない。
- 数値の対応は dotfiles の `infra/ai/textlint/README.md` を見る。

## 警告の扱い

- 警告は修正候補であり、合否ではない。警告ゼロを公開条件にしない。
- 読点を削るだけの修正や、条件や否定を失う短縮をしない。制限回避のための改行やリスト化もしない。
- 分割すると意味が壊れる文や、固有名詞やコマンドを含む文は残してよい。
- 警告解消だけを目的に修正を繰り返さない。
