# Issue #16 Light / Darkテーマ実装

## 目的

Issue #16で確定したキーボード画像由来paletteを、system追従のLight / DarkテーマとしてWeb UIへ
適用する。

## 判断

- 画像由来色は`tokens.css`の`--palette-*`へ無補正で置き、semantic tokenから参照する。
- hover、soft background、errorなど画像に無い状態色は`--derived-*`またはsemanticな派生tokenとして
  sampled色と区別する。
- 接続状態と選択状態のclassを分離し、successとprimaryを別の意味で使う。
- 文字と主要操作は4.5:1、focusとcontrol境界は3:1以上を自動テストする。
- theme selectorは追加せず、`prefers-color-scheme`追従を維持する。

## 変更

- Light / Darkのsampled palette、semantic token、derived状態色を定義した。
- keymap、picker、header、diagnostics、Apply UIへ状態別tokenを適用した。
- sampled値、system追従、contrast、raw hexの単一定義元を回帰テストへ追加した。
- `docs/specs/ui.md`へthemeの実装契約を追加した。

## DocBridge Sync判断

related gateは`docs/specs/ui.md`の既存22 counterpartを報告した。追加したtheme節は既存annotationの
外側で、workspace、geometry、編集、diagnostics、Apply状態機械の契約を変更しないため、それらの
counterpart更新は不要と判断した。Headerは接続済みを文字でも示す契約、Applyはbackupを先頭に示す
5 step契約を維持しており、今回のclass変更は両契約の配色だけを具体化する。
