# 2026-08-19 D-004 workspaceとlocalhost serviceの構成を決める

対象Issue: #9 `[D-004] workspaceとlocalhost serviceの構成を決める`

## 調査方法

- ADR 0002・0003・0005 がD-004へ送った要求（definitionの置き場、xz decoder、
  backupの置き場）を洗い出した
- `.gitignore`の既存の記述から、Git管理対象と生成物の線が既に引かれていることを確認した
- 配置規則とdefinitionの対応づけをSpike（`spikes/d-004-workspace/`）で検証した
- File System Access APIの権限復帰を確認するbrowser probeを用意し、2026-08-19にChromium系browserで手動実行した

## Fact

- `.gitignore`は既に`cornix/generated/`と`cornix/backups/`を無視している。
  workspaceの配置はこの時点である程度決まっていた
- `DecompressionStream`が扱えるのは`gzip` / `deflate` / `deflate-raw`のみ。**xzは扱えない**
- Nodeにもxzの組み込み実装は無い。したがって**xz decoderの追加は
  browser-only案とlocal service案の判断材料にならない**
- ADR 0004 でWebHIDを採用した時点で対象browserはChromium系に確定している。
  `showDirectoryPicker`も同じ制約下にあり、browser-only案の追加コストはゼロ
- File System Access APIのdirectory handleはstructured cloneできるため、
  IndexedDBへそのまま保存できる

## Spike結果

`spikes/d-004-workspace/self-check.mjs`（実機もbrowserも不要）は全チェック通過。

- `.gitignore`の無視範囲とworkspaceの生成物の範囲が一致する
- definitionのcontent-addressingが成立する（同じ内容なら同じdigest、1 byte違えば別のdigest）
- keymapとdefinitionの対応づけで、digest不一致とkeyboard uid不一致の両方を検出できる
- backupのファイル名が辞書順と時刻順で一致し、Windowsで使えない文字を含まない
- `DecompressionStream("xz")`は例外になる

fixtureのdefinitionのdigestは`49610cdbc2ca7307b9495eae003fe6b478882eade97402318fb66206acf869f2`。

**browser probe（`index.html`）を実行した。** File System Access APIのdirectory pickerは
OSのネイティブダイアログであるため、手動で検証した。

### 手動確認結果

- 手順1で検証用workspace `test`を選択し、手順2で`keymap.yaml`、definition、backupを書き込めた
- ページをリロードした後、手順3で`リロード直後の権限`が`granted`となった
- ディレクトリを再選択せず、保存済みhandleから`keymap.yaml`を読み書きできた
- 手順4でworkspace外から`keymap.yaml`を変更し、再読み込み後に`keyboard.name`が
  `Cornix LP  ljljljlj-l`へ変わって表示された。外部編集の取り込みが成立した
- 検証用workspaceの生成物は確認後に削除した。実機接続、WebHID、firmware writeは行っていない

## Decision

ADR `docs/decisions/0007-workspace-layout.md`（**状態: 採用**）に記録した。

Browser標準APIだけで閉じ、local serviceを置かない案を採用する。
File System Access APIの権限はリロード後も復帰し、外部編集も明示的な再読み込みで取り込めた。

## Open Question

- browserで動くxz decoderの選定が未了。依存追加の判断を伴う
- file watchingを持たない前提のため、編集の衝突検出をどうするかが未検討
- `keymap.yaml`のschema自体はD-002。ここで決めたのは先頭の対応づけheaderの形だけ
