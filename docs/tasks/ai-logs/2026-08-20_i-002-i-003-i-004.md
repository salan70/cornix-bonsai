# I-002 / I-003 / I-004 MVP実装

## Fact

- Issue #13〜#15はworkspace/editor/CLI、WebHID adapter、Safe Apply UI統合を対象にしている。
- 実装前のリポジトリには`src/core/`だけがあり、frontend・workspace adapter・CLI・production device adapterは無かった。
- `fixtures/cornix-lp/`と既存Coreのround-trip / validation / Apply testは存在した。
- 実機USB/BLEのfull readとwriteは、この作業では実行していない。

## 実装

- Vite + React + TypeScriptのfrontendを追加し、4 tab、side panel、status bar、Apply modalを実装した。
- File System Access APIのdirectory handleをIndexedDBへ保存し、reload後に復帰するBrowser workspace adapterを追加した。
- Apply warningのacknowledge IDを`cornix/acknowledgements.json`へ保存し、最新backupの復元を通常のdesired/diff/Apply経路へ接続した。
- Behaviors tabにTap Dance / Combo / Settingsの直接編集を追加した。
- Node workspace adapterと`cornix validate/analyze/diff/render/export vil`、`.vil import` CLIを追加した。
- SVG/PDF rendererをdefinition由来の同一座標から生成するようにした。
- Vial report session、definition/full read、matrix由来layout、single-entry write + reread verify、timeout/disconnect境界を追加した。
- write未対応のmacro/unknown field/layout option差分はApplyをfatalで止め、I/O timeout/disconnect/protocol errorはaborted stateへ遷移させるようにした。
- xz definition decodeにはbrowser/Node対応の`xz-decompress`を使った。
- `MockHidDevice`でwrite command、再read verify、timeout、disconnectを自動検証した。
- Cornix LP V1.12のqsid辞書（9項目）をUI表示へ追加し、未知qsidはraw表記へフォールバックするようにした。
- Apply modalをnative`<dialog>`へ揃え、write開始後は中断だけを許可し、進行中I/O完了後に未完了分を破棄するようにした。
- Apply差分へqsid辞書を渡し、`notationOnly`差分を折りたたみ表示にした。Keymapのside panelにもsemanticな挙動説明を表示する。
- WebHID input reportのreport ID / 32-byte契約を検証し、非対応のkey override / alt repeat件数をprotocol errorで止める境界を追加した。
- workspaceのdefinition bindingをpathと実体bytesのSHA-256で検証し、UI/CLIの両方で改変definitionを拒否するようにした。
- macro表記をwire protocolと同じ`M(n)`へ統一し、参照解析・範囲検証・未使用macro表示の取りこぼしを修正した。
- Keymap tabへencoder strip、keycapのlayer/modifier/Tap-Hold表示、macOS modifier glyph、arrow/Enter/Esc keyboard操作を追加した。
- Apply開始時にfull-read backupを先に保存し、`awaitingConfirmation`中はwriteせず、確認後だけsingle-entry write + reread verifyへ進むようにした。接続・再読込・definition mismatchで古いApply計画も破棄する。

## レビュー指摘への対応（#13 / #14 / #15）

### 前提

- Issue #13 / #14 / #15 のレビューで合計9件がblockingとして挙がった。うち6件がコード、
  3件が実機・手動acceptanceである。
- 対応開始時点のコードを確認したところ、6件はいずれも未修正のままだった。

### 対応（コード）

- `layout_options`のread条件を`layouts.labels`の宣言へ揃えた（#14 Blocking 1）。
  labelsだけを持つCornix LPで`-1`になり、baselineの`0`と偽差分になっていた。
- wire値 → keycode表記の逆変換を`encodeVialKeycode`の逆写像としてSemantic Coreへ置いた
  （#14 Blocking 2）。baselineの全125表記でencode → decode → encodeが同値になる。
  modifier別名と`0x0200 | basic`は`.vil`の表記と一致する側へ固定し、`TD(n)` / `M(n)`は
  実機申告capacityの範囲内だけ表記へ戻す。
- definitionのcontent-addressingをcanonical表現（キー辞書順 + 2 space整形 + 末尾改行）の
  SHA-256に統一し、CLI import・実機read・binding検証を同じ関数へ通した（#15 Blocking 1）。
  規則が変わったためfixture definitionのdigestを`2e27d796…`へ再計算した。ADR 0007と
  `docs/specs/workspace-cli.md`へ規則を追記した。
- `keymap.yaml`への保存を直列queueへ分離した（#13 Blocking 2）。編集は同期的にstateへ反映し、
  writeとtoken更新はqueueだけが行う。
- Apply成功後に実機をfull readし直してcurrent stateを収束させた（#15 Blocking 2）。
- `navigator.hid`のdisconnect eventをconnectionが購読し、idle切断でdevice由来のstateを
  まとめて捨てるようにした（#15 Blocking 3）。

### 対応後の検証

- `nix develop -c pnpm test`: 124 tests passed（追加14件）。
- `nix develop -c pnpm typecheck` / `pnpm run build` / `just lint`: passed。
- CLI smoke: 一時workspaceへ`import vil` → validate（error 0 / warning 0）→
  diff 0件 → SVG / PDF render → `export vil`がbaselineとbyte一致。
