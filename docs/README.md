# ドキュメントの責務と運用

リポジトリ内のドキュメント構成、責務分担、正本ルールを定めます。

## ドキュメントの分類と責務

| 配置場所         | 対象読者       | 記録内容と責務                                               |
| ---------------- | -------------- | ------------------------------------------------------------ |
| `user-guide/`    | 利用者・運用者 | Web UI や CLI の操作手順、安全な書き込み、障害復旧、用語解説 |
| `decisions/`     | 開発者・AI     | 設計上の重要判断とその根拠（ADR）                            |
| `specs/`         | 開発者・AI     | コードと 1:1 で対応する実装仕様（DocBridge で双方向リンク）  |
| `tasks/ai-logs/` | 開発者・AI     | AI エージェントの作業記録（日付・作業単位）                  |
| GitHub Issue     | チーム全体     | 進行中の調査、設計課題、Spike、作業タスクの管理              |
| Tests / fixtures | 開発者・CI     | 仕様や変換処理が正しく成立することの自動検証                 |

## 正本ルール

情報の散乱と不整合を防ぐため、以下の正本ルールを適用します。

- **利用者向け手順**: `user-guide/` を正本とします。
- **実装の振る舞い**: `specs/` を正本とし、コードと DocBridge で機械検証します。
- **設計判断の根拠**: `decisions/`（ADR）を正本とします。
- 同一の仕様や詳細を複数箇所へ複製して記述することを禁止します。

## 読者別の参照案内

### 利用者・キーマップ運用者

1. [利用者ガイド Top](./user-guide/README.md) で対応環境とクイックスタートを確認します。
2. 実際の操作に応じて [Web UI](./user-guide/web-ui.md) または [CLI](./user-guide/cli.md) を参照します。
3. 実機書き込み時は [Safe Apply と復旧](./user-guide/safe-apply.md) の手順に従います。

### 開発者・コントリビューター

1. ルートの [README.md](../README.md) で開発環境をセットアップします。
2. 仕様の変更時は `specs/` を更新し、リンク整合性を検証します。
3. 重要な設計方針の変更がある場合は、`decisions/` へ ADR を追加します。
