# 編集対象と作業を分離したナビゲーション

状態: 採用

2026-09-22に、uiux-numaのたたき台比較と利用者フィードバックを受け、編集対象を常時表示するTarget + Work構成へ更新した。
参照元はuiux-numa commit `4b3472e` の `chromatic-rail-library` である。

## 背景

従来の編集対象ドロップダウンは、現在どのキーボードを編集しているかを選択中以外の状態から判断できなかった。
対象別にタブを入れ替える構造は、キーボードの種類が増えるほどナビゲーション項目を増やす方向へ誘導する。
利用者はTarget Libraryの対象一覧表示と、Chromatic Rail Nextの縦レール、色面、編集ステージ、右インスペクターの組み合わせを選んだ。

## 選択肢

1. 編集対象をドロップダウンで選び、対象別のタブを入れ替える。
2. 編集対象を左レールへ常時表示し、下へ共通の作業項目を固定配置する。
3. 編集対象を一覧ページへ移し、編集画面では対象を表示しない。

## 決定

案2を採る。
編集対象はCornix LP、Mac ANSI、Mac JISをカードとして常時表示し、選択中のカードを面と境界で示す。
作業項目はキー割り当て、全体マップ、動作定義、検証の順に固定する。
選択対象で利用できない作業は非表示にせず、位置を維持した無効表示と理由の説明を出す。
対象を切り替えた時点で現在の作業が利用できない場合は、キー割り当てへ移動し、statusで理由を伝える。
保存状態と実機へのApplyは作業ナビゲーションから分離し、画面下のstatus barへ残す。

## 理由

案1は現在の選択対象が視界から消えるため、複数対象を切り替える作業の認知負荷が高い。
案2は対象と作業の2軸を同じレールに置き、対象追加時も既存の作業位置を動かさずに済む。
案3は対象変更のために編集コンテキストを離れるため、連続編集と保存状態の確認に向かない。

## 影響

`WorkTask`を内部の画面状態として追加したが、workspace、keymap、Mac設定、Apply、CLIの公開形式は変更しない。
`EditTargetSelect`はselectではなく、キーボード操作可能な対象カードを描画する。
既存のCornix / Mac専用コンポーネントは、共通作業から選ばれた内容を描画する責務として維持する。

## 却下理由

ドロップダウン案は対象の常時把握を満たさないため却下した。
対象一覧ページ案は編集画面と対象選択を分断するため却下した。
